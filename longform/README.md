# Long-form videos (work in progress)

Long 16:9, 1080p versions of Reckon's animations, 5–15 minutes each, for watching on a computer or YouTube. Each video comes in two versions: one narrator, and a dialogue in which two narrators talk the story through (`<slug>-dialogue/`, which shares its scene with `<slug>/`).

This folder is a saved copy of the studio the videos are made in. The tools still use the studio's own paths. Recordings, renders, stills and downloaded research pages are left out because they can all be made again.

- `BRIEF.md`, `DIALOGUE.md`: what a video's writer does.
- `<slug>/script.mjs`: the narration as keyed lines, with its sources. `scene.js`: the animation, keyed to those lines. `timeline.js`, `subtitles.srt`, `plan.json`: the timing measured from the recorded voice. `music.json`: the soundtrack plan. `voice.txt`: the voice or the cast.
- `tts.sh` records the lines and runs `timing.mjs`. `render.mjs` draws stills or video. `render-video.sh` renders a video, then `assemble.py` builds the speech track and `mix.py` mixes it with the music. `music-remap.mjs` moves a monologue's music plan onto its dialogue's timeline.
- `page.html` loads `kit.js` and `fonts/` from `explainers/`.
- `app.sh` makes the phone app's copy of a finished video and its poster.

## French version

A single-narrator video can also have a French version (a dialogue can't, yet). It shares the English video's scene: the French voice gets its own timeline, and since the scene is keyed to line keys it plays to that timing unchanged, while kit.js swaps the text it draws for French. `test-fr/` is a small example with every file a French version needs (six lines, two chapters).

- **Script.** `script.mjs` also exports `FR = { <key>: { text, say? } }`, with every key of `LINES`. `text` is the French subtitle. `say` is what the voice reads where that differs: numbers and years in words, and no final full stop (it's dropped anyway, because XTTS sometimes reads it out as "point"). It may also export `HOLD_FR = { <key>: seconds }`, which overrides `HOLD` on the French timeline; any key it doesn't name keeps its `HOLD` value. Gaps and chapters come from `LINES`.
- **On-screen text.** `labels-fr.json` is `{ "labels": { "English": "Français", … } }`, with the French for every whole string the scene draws, written exactly as it is drawn: the chapter titles as the scene draws them (`"TWO TIMELINES"`, `"PART 1"`), the credits, and names that stay the same, mapped to themselves. `render.mjs` sets it as `window.TR` (with `locale: 'fr-FR'`) before kit.js loads. From then on, every string drawn with fillText, strokeText or `k.rich()` is swapped for its French, and measureText measures the French too, so layouts follow the longer text. `Kit.fmt` writes `1 250 000`. In French, `page.html` makes it group thousands with a no-break space (U+00A0) instead of kit's narrow U+202F. Most families in the library lack U+202F, and the browser draws it almost without width (1250000). For the same reason, use U+00A0 in labels; the subtitles can keep U+202F. A string put together in code (`` `${n} km` ``) has no whole-string label, so draw words and numbers as separate strings. Kit.fmt only does whole numbers: a decimal needs `x.toLocaleString(window.TR?.locale ?? 'en-US', …)`, or it is drawn as `7.2` in French too.
- **`bash tts-fr.sh <slug>`** records the French lines with XTTS-v2 (speaker Ana Florence), each at its natural pace. It runs `node timing.mjs measure-fr <slug>` first, which flags digits, symbols, colons and over-long lines in what the voice will read. `frvoice.py` then uses the French short clips' `fr/narrate.py` (take, heard, score, tail, rise, spoken). Each take is checked with French speech recognition (faster-whisper): the words heard, nothing said after the last word, no rising end on a statement, and no rushed or drawn-out pace. A take that fails is recorded again with another seed, up to four takes. A line's result is cached by its exact words in `rec-fr/cache/`, so a re-run records only new or reworded lines. The script writes `rec-fr/<key>.wav`, `measure-fr.json` (`{ key: seconds }`) and `rec-fr/report.txt` (every line, with what was heard), and lists the lines that still need checking. Then it runs `node timing.mjs build-fr <slug>`, which writes `timeline-fr.js` (the same `window.TL` shape, with the chapter titles still in English for the labels to translate), `subtitles-fr.srt` and `plan-fr.json`. Finally `node music-remap.mjs <slug> --fr` checks that the music plan fits the French timeline. **Only one XTTS process may run on this machine**: the recording waits for `xtts.lock` and uses 3 threads.
- **`node render.mjs preview <slug> t1,t2,… fr`** writes French stills to `prev-fr/`. It also prints the font check and every text still drawn in English. `scan` and `video` take `fr` as their last argument too.
- **`bash render-video.sh <slug> fr`** renders the French picture into `<slug>/fr/`. `music-remap.mjs <slug> --fr` moves the music plan onto the French timeline by chapters and writes `music-fr.json`. It stops before rendering if a track runs short. `assemble.py <dir> fr` builds the speech track from `plan-fr.json` and `rec-fr/`, and `mix.py <slug> fr` mixes `<slug>/<slug>-fr.mp4`. It uses the same locks as the English render, so **final renders run one at a time**. Without `fr`, everything is as before.
- **`bash app.sh <slug> [fr]`** makes the phone app's copy from the finished 1080p video, `<slug>/app/<slug>[-fr].mp4`: 1280×720, H.264 high profile level 4.0 with `-tune animation`, CRF 23 capped at 560 kb/s, AAC 96 kb/s stereo, faststart, and a keyframe at least every 4 s. That comes to at most about 5 MB a minute; the busiest existing video, sky-blue, needs about that much. It also writes a 1280×720 JPEG poster, `<slug>/app/<slug>[-fr].jpg`. The poster is the frame 0.3 s before the first chapter card, where the cold-open title stands. To use another frame, export `POSTER = ['<key>', <seconds after that line starts>]` from `script.mjs`. It prints the sizes and the longest gap between keyframes, and takes `render.lock` like a render.
- A central job for one video in both languages: `bash finalize.sh …` (English, as before), then `bash tts-fr.sh <slug> && bash render-video.sh <slug> fr && bash app.sh <slug> && bash app.sh <slug> fr`.
- `tts-fr.sh` needs the XTTS venv (`scratchpad/xtts-venv`) and `scratchpad/fr/narrate.py`. Neither is saved in this folder.
